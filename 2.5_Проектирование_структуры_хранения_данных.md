# 2.5 Проектирование структуры хранения данных

В отличие от классических информационных систем (например, CRM или интернет-магазинов), специфика системы управления компьютерным классом «ClassControl» не требует использования тяжеловесных реляционных баз данных (таких как MySQL или PostgreSQL). Архитектура приложения подразумевает сессионный характер работы: абсолютное большинство данных актуальны только во время проведения текущего урока. В связи с этим структура хранения данных разделена на два уровня: оперативную память (для активных состояний сессии) и файловую систему (для долгосрочных артефактов).

**1. Хранение состояний в оперативной памяти (In-Memory Storage)**
Центральный сервер (Node.js) выступает в роли единого источника истины (Single Source of Truth) для текущего урока. В оперативной памяти сервера хранятся следующие структуры данных:
* **Список активных агентов (`agents`):** Массив объектов, содержащий уникальные идентификаторы сокетов (Socket ID), имена компьютеров, IP-адреса и статусы локальных учеников в классе.
* **Список удаленных участников:** Аналогичный список для пользователей, подключенных через обозреватель.
* **Состояние трансляции (`isBroadcasting`):** Логический флаг, указывающий, идет ли в данный момент эфир. При подключении нового ученика сервер проверяет этот флаг и, если он активен, немедленно дает команду агенту развернуть окно приема видеопотока.
* **Снимок интерактивной доски:** Массив инструкций рисования или снимок холста. Это необходимо для того, чтобы ученик, опоздавший на урок и подключившийся позже, получил актуальное состояние доски, а не чистый экран.
Такой подход обеспечивает максимальное быстродействие системы, исключая задержки на дисковые операции ввода-вывода при обработке сотен сообщений в секунду.

**2. Хранение артефактов в файловой системе (File System Storage)**
Данные, которые должны сохраниться после завершения урока, записываются непосредственно на жесткий диск:
* **Видеозаписи уроков:** При нажатии кнопки «Запись» приложение преподавателя осуществляет локальный захват экрана и звука. Данные сохраняются на компьютере преподавателя в папке для записей.
* **Файловый обмен в области сообщений:** Если участник отправляет файл в общую беседу, он передается на сервер с использованием промежуточного программного обеспечения. Файл физически сохраняется на диске сервера. Вместо передачи самого файла, в сообщении содержится только ссылка на его скачивание.
* **Конфигурация агентов:** Локальные настройки агентов учеников, включая запрет на закрытие программы и автозапуск, сохраняются в системном реестре Windows.

Спроектированная комбинированная структура хранения обеспечивает высокую производительность обмена в реальном времени и надежное файловое сохранение образовательных материалов без оверхеда на администрирование баз данных.
