# 2.4 Проектирование алгоритмов взаимодействия модулей

Работа системы «ClassControl» построена на алгоритмах обмена данными в реальном времени. Учитывая распределенный характер системы, критически важно обеспечить надежную логику обнаружения узлов, установки соединений и передачи данных мониторинга.

**Алгоритм автоматического обнаружения**
Для исключения необходимости ручной настройки сетевых адресов в локальной сети реализован алгоритм автоматического поиска сервера путем широковещательных рассылок, схема которого представлена на рисунке 2.2.
1. При запуске приложения преподавателя инициализируется сервер, который начинает прослушивать порты для подключения и широковещательных запросов.
2. При запуске фонового агента на компьютере ученика приложение отправляет широковещательный запрос во всю подсеть класса.
3. Сервер преподавателя, получив данный запрос, отправляет ответное сообщение, содержащее свой актуальный локальный IP-адрес.
4. Агент ученика извлекает IP-адрес из ответа и инициирует постоянное WebSocket-соединение с сервером.

**Алгоритм мониторинга экранов**
Процесс передачи изображений рабочих столов учеников оптимизирован для работы в фоне:
1. После успешного подключения агент инициализирует встроенный модуль захвата из платформы Electron.
2. Раз в секунду агент делает снимок основного экрана.
3. Для снижения сетевой нагрузки снимок сжимается до 30% качества и уменьшается в разрешении до базовых 320x180 точек.
4. Сжатое изображение отправляется на сервер по сети.
5. Сервер маршрутизирует данное сообщение в приложение преподавателя, где обновляется соответствующая карточка в сетке мониторинга.

**Алгоритм установки медиа-соединения**
Для проведения полноэкранной трансляции или дистанционного управления используется прямое соединение устройств. Алгоритм его установки работает через уже созданный сетевой канал:
1. Инициатор, например преподаватель при запуске трансляции, формирует техническое предложение, описывающее параметры видео и звука.
2. Это предложение передается через сервер нужному ученику или всем участникам сразу.
3. Приложение ученика принимает параметры трансляции и формирует встречный ответ, подтверждая свою готовность.
4. Ответ отправляется обратно инициатору. Параллельно происходит обмен техническими адресами для установления связи в обход маршрутизаторов.
5. После этого согласования видеопоток начинает передаваться напрямую между компьютерами, минуя центральный сервер.
