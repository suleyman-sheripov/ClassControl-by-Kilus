# 🎤 Сценарий озвучки видео-демонстрации ClassControl

## Часть 1: Обзор приложения Учителя и Мониторинг

**[Действие на экране: Учительское приложение открыто на весь экран. Водишь мышкой по интерфейсу слева направо.]**

**Текст:**
«Демонстрацию работы системы я начну с основного пульта управления — приложения Учителя. Оно разработано как десктопное приложение на базе фреймворка **Electron**, что дает прямой доступ к системным API операционной системы. 

Слева расположена панель коммуникации со встроенным чатом, в центре — рабочая область мониторинга, а справа — панель управления трансляцией (студия эфира). 

Главная особенность мониторинга — это низкая задержка. Изображения с локальных компьютеров собираются с помощью нативного модуля **Electron desktopCapturer**. Для экономии пропускной способности сети скриншоты сжимаются в JPEG на лету и транслируются на сервер через сокет-соединение с частотой один кадр в секунду».

## Часть 2: Онлайн-доска и Запись экрана

**[Действие на экране: Переключаешься на вкладку "Доска". Рисуешь пару простых фигур. Затем переводишь курсор на кнопку 🔴 Запись в шапке окна и нажимаешь её на пару секунд, потом выключаешь.]**

**Текст:**
«Перейдём к инструменту Онлайн-доски. Это ключевой элемент для разбора задач. Технически доска реализована на базе **HTML5 Canvas**. Когда я рисую, алгоритм захватывает координаты точек и передает их в виде легковесных JSON-объектов по протоколу **WebSocket** (через библиотеку **Socket.IO**). Это обеспечивает мгновенную синхронизацию отрисовки у всех участников-клиентов.

Также в системе встроена функция фоновой записи урока. Для этого используется встроенный в браузерный движок API **MediaRecorder**, который захватывает видео- и аудиопоток текущего окна и на лету сохраняет его в формат WebM прямо на локальный диск».

## Часть 3: Взгляд со стороны онлайн-участника

**[Действие на экране: Открываешь половину экрана с браузером. Вводишь имя, нажимаешь "Присоединиться". В окне Учителя переключаешься между Доской и Мониторингом, показывая, как меняется экран в браузере.]**

**Текст:**
«Теперь посмотрим, как всё выглядит для дистанционного ученика. Онлайн-интерфейс работает в любом современном браузере. Под капотом здесь крутится **Node.js и Express**, раздающие статику. 

Как только участник подключается, он автоматически подхватывает состояние комнаты. Обратите внимание — переключение контекста у преподавателя мгновенно отражается у студента. Логика синхронизации состояний (State Management) обрабатывает события на бэкенде: если учитель включил доску, сервер широковещательно рассылает сигнал (broadcast) всем подключенным клиентам для переключения интерфейса».

## Часть 4: Трансляция экрана участника (с ограничением по времени)

**[Действие на экране: В окне браузера ученика нажимаешь "📺 Показать мой экран". Появляется таймер. Затем от лица Учителя выключаешь трансляцию ученика.]**

**Текст:**
«Онлайн-студент может продемонстрировать свой экран для проверки задания преподавателем. За захват и передачу живого видео отвечает передовая технология **WebRTC**. В отличие от Websocket сообщений, видео идет по Peer-to-Peer шифрованному каналу, минимизируя нагрузку на сервер. 

Чтобы избежать саботажа или зависаний эфира, я внедрил специальный алгоритм-таймаут: сессия демонстрации экрана ученика жестко ограничена пятью минутами. Учитель же в любой момент может принудительно перехватить контроль и разорвать соединение с помощью специального управляющего пакета через сигнальный сервер».

## Часть 5: Взгляд со стороны Агента (локального ПК)

**[Действие на экране: Показываешь иконку в системном трее Windows. Нажимаешь правую кнопку мыши, открываешь беседу. Показываешь окно чата.]**

**Текст:**
«Что касается агентов — то есть локальных компьютеров в самом классе — их приложение работает абсолютно незаметно (в фоновом режиме в системном трее) и не отвлекает учеников. Авторизация клиентов происходит по локальной сети через бессерверный алгоритм **UDP LAN Discovery**. Агенты слушают сеть и автоматически находят сервер без необходимости вручную вводить IP адреса.

На данный момент со стороны ученика в классе доступна возможность общаться в чате и обмениваться файлами. В то же время, учитель обладает правами суперпользователя в этой экосистеме, позволяя ему через этот же канал отправлять низкоуровневые IPC-команды для полного удаленного управления мышью и клавиатурой локальных агентов».
